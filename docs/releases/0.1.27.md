# Nektron Moments 0.1.27 — scrolling preparation

The scrollbar still exposes the familiar 200/500 positions. Caching is separate:
nearby worker-decoded thumbnails are made display-ready in small idle UI batches
(up to 1,000 on this workstation), while deeper lookahead stays compressed. Four
asynchronous uploads may overlap, but only one starts per render frame during
input. Foreground requests take priority; optional work yields during input and
is canceled on view changes. Original media and saved arrangements are unchanged.

## Evidence and limits

Tests use the real 144,881-item library, small thumbnails, and native in-app
scroll commands. These are XAML render callbacks, not physical mouse replay or
GPU-present FPS. Startup, warming and rendering all run on the actual Windows
app; automatic metadata and AI processing are disabled during diagnostics.

An alternating cold comparison found baseline 33 callbacks/sec versus candidate
32: no meaningful motion-rate gain. Candidate display-source creation improved
from 97 to 240–245, with queued foreground requests falling from 310–334 to 87–92.

With eight seconds of idle preparation, display warming alone improved a paired
probe from 33 to 43 callbacks/sec. Keeping deep lookahead compressed then reached
50 callbacks/sec and reduced measured GC pauses across startup plus the probe
from about 2.6 seconds to 0.53 seconds. UI dispatch p95 in that run was 23 ms.
These observations support better readiness/less startup pressure, not a claim
of sustained 120 FPS. Physical scrollbar feel still needs user comparison.

Rejected experiments: moving native bitmap creation to presentation worsened
cold cadence; larger control caches and disabling stock transitions produced no
measurable win. Caption phasing was also removed. Existing rearrangement motion
and scrollbar geometry are preserved.

Final candidate repeated the real-library result: 51.2 render callbacks/sec,
23.2 ms UI dispatch p95, 0.56 seconds of GC pauses across startup plus the probe,
and no queued foreground presentations remaining at the end. No AI jobs were
started and saved order was unchanged.

Release validation: 494 Python tests, 953 C# assertions, 129 native workflow
checks, 32 photo-opening checks, the 100,000-item scrolling suite and installed
canary passed. The known timing-sensitive animation check now samples on render
callbacks instead of a wall-clock timer, retaining its intermediate-motion and
retarget assertions. Production animation behavior is unchanged.
