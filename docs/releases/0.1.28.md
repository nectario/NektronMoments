# 0.1.28 — Enrichment catch-up

The run allowance is now independent of the 64-asset HTTP transaction size.
Settings and the processing window accept 1–1,000,000 assets per source and
offer a 10,000-asset shortcut. Existing saved preferences and the default remain
unchanged: upgrading must not silently expand a user's automatic paid run.

The client prepares and persists one page, stages previews, then advances a
source-scoped asset cursor. Completed descriptions and already queued jobs are
not selected again. Preparing jobs with unreadable local originals cannot trap
the run on the first page. Quota deferral stops requesting further pages;
ordinary saved-outbox/idempotency behavior handles interrupted work.

Run allowance is an upper bound, not a guarantee of completed descriptions.
Existing queued work may finish separately. Estimates scale with the selected
allowance; the production monthly $230 scene budget and call limits remain
server-enforced and unchanged. No live paid catch-up is part of release tests.

## Subscription boundary

The 1,000,000 ceiling is a technical guard, not a product plan. Before public
launch, introduce account/plan entitlements and atomic server-side period usage
checks at job reservation/admission, shared by Windows, mobile and CLI. Return
remaining allowance and renewal information to clients; never trust a client
Settings value as a subscription entitlement. Plan names, prices and quotas
remain undecided. The current provider-cost budget stays separate from those
future product entitlements.

Splash preparation and the expanded model catalog are separate pending work;
this release addresses the catch-up limit only.
